# Codex Session Tracker

A tiny local web app for people who run many [Codex](https://openai.com/codex) sessions in parallel over days. It shows
all your sessions (Codex Desktop, IDE extension and CLI) as a tree, **with forks and spawned subagents nested under the
session they came from**, and lets you keep your own notes per session: goal, now, next, later, a log, and a linked
GitHub issue. When you come back to a session, click **Summarize** to get an on-demand summary of your conversation with
Codex: the goal, what was done, the current state, blockers and a suggested next step.

- Python 3.9+ standard library only, one static HTML page, no build step, no dependencies.

## Features

- **Session tree**: sessions grouped by your Codex sidebar sections, repo or folder. User forks and spawned subagents are
  nested under their parent; guardian/review/summarizer threads are hidden by default.
- **Status**: active (< 15 min), recent (< 24 h), idle, archived; open/closed badge for subagents.
- **Grouping**: *Sections + repo + folder* (default), *Sections only* (mirrors the Codex sidebar order and counts,
  including Codex Cloud tasks), *Repo only*, *No grouping*. Choice persists (`?group=sections|repo|none`).
- **Notes per session** with autosave; the *Next step* column shows what each session is waiting on.
- **GitHub**: link an issue (`123`, `#123`, `owner/repo#123` or URL); title/state via `gh` (cached). Branches like
  `feat/123-foo` suggest `#123`. PR attachments recorded by Codex show their state.
- **Open in Codex**: `codex://threads/<id>` deep links (side panel button + per-row icon); cloud tasks link to Codex Cloud.
- **On-demand summary** of a session (goal, what was done, current state, blockers, suggested next step, related
  issues/PRs) generated by your own Codex CLI. Shows when a summary is outdated; one click copies the suggested next step
  into *Next*. Never runs automatically.
- Search across titles, notes, summaries, branches, folders and ids. `#<thread-id>` deep-links to a session.

## Run

```bash
python server.py            # http://127.0.0.1:8765/ opens in your browser
python server.py --port 9000 --codex-home /path/to/.codex --no-browser
```

Windows helpers: `powershell -ExecutionPolicy Bypass -File start.ps1` (starts hidden, opens the browser) and `stop.ps1`.

Optional: [GitHub CLI](https://cli.github.com/) (`gh`) logged in, for issue/PR titles; the Codex CLI for summaries
(the CLI bundled with Codex Desktop is preferred on Windows/macOS, otherwise `codex` on `PATH`).

| Env var | Purpose |
|---|---|
| `CODEX_HOME` | Codex data dir (default `~/.codex`) |
| `TRACKER_PORT` | Port (default 8765) |
| `TRACKER_DATA_DIR` | Where `notes.db` and `.summarize/` live (default: next to `server.py`) |
| `TRACKER_CODEX` | Path to the Codex CLI to use for summaries |
| `TRACKER_SUMMARY_MODEL` / `TRACKER_SUMMARY_ARGS` / `TRACKER_SUMMARY_TIMEOUT` | Summary model, extra CLI args, timeout (s) |

## Privacy and safety

- **Read-only on Codex data.** Opens `state_5.sqlite` with `mode=ro`, reads `session_index.jsonl`,
  `.codex-global-state.json` (sidebar sections) and rollout files. It never writes under `CODEX_HOME` and never reads
  `auth.json`.
- **Local only.** Listens on `127.0.0.1`; rejects foreign `Host`/`Origin` headers and non-JSON POSTs.
- **Your data stays in `notes.db`** (notes, summaries, a cache of fork links). It is git-ignored; don't publish it.
- **Summaries** send a compact transcript of the selected session (your messages, Codex's answers, one-line tool calls;
  no reasoning, tool output or injected context) to your Codex CLI:
  `codex exec --ephemeral --sandbox read-only --ignore-user-config --ignore-rules --skip-git-repo-check`
  in a scratch folder. `--ephemeral` means no new Codex session is saved; it uses your existing Codex login and
  your default `model` from `config.toml`. This uses your Codex usage like any other request.

## Disclaimer

This project is not affiliated with OpenAI. It reads **undocumented internal Codex files** (SQLite schema, rollout JSONL
format, Desktop UI state) that can change in any Codex release; things may break or show incomplete data after an
update. Fork links, sidebar sections and cloud tasks are best-effort reconstructions.

## Tests

```bash
python tests/run_tests.py
```

Builds a synthetic Codex home in a temp dir, runs the server against it with a fake `codex` CLI, and checks the API,
summaries and (if Chrome/Chromium/Edge is installed) the rendered UI.
